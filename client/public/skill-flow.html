第 1 步核心能力：实体落地核查（MCP 远程访问 HA）

判据里引用的实体不凭记忆和想象写——Agent 经 MCP 工具远程拉取实体当前状态与历史记录验证可落地；不通过或口径不全时，在多轮对话中吸收用户补充，再重新核查，直到定稿。

远程只读查询（只拉状态与历史，不写 HA） 澄清回路：用户多轮补充 → 并入判据 → 重新核查 定稿后仍要过第 2 步流程图确认门禁

第 5 步细分：影子验证链（验收门禁）

仿真只验证流程 / 时序 / 写意图，结果不能直接当上线依据；三段走完才有资格进入第 6 步。

只有用户放行才推进 · 影子硬隔离保证全程碰不到真实设备

版本角色与生命周期

每版本 meta.channel 四选一；影子 / 正式各至多一个。这就是「影子可反复改、正式不可变」的机制基础。

贯穿全程的硬规则

规则口径
影子硬隔离影子实例的所有 HA 写调用被主进程拦截、只记日志；脚本绕过 ctx.write 也拦——两层保障缺一不可
绝不自动发布正式版本必须用户验证后确认发布；「发布」= 影子转正式，旧正式自动归档
读不隔离 / 写隔离ctx.global.get / watch / task.* 统一读 production；ctx.global.set 按调用者通道落桶
单写者约定每个 global 键只能有一个写者脚本；订阅方通过折叠通道（值 + 写者状态）感知依赖健康
实体现状先行判据引用的实体一律经 MCP 工具远程拉当前状态与历史记录核对（存在性 / 单位量程 / 历史能否支撑判据），不凭记忆写实体 id；多轮对话中用户补充的口径即时并入需求，不视为推倒重来
存储分层跨脚本共享 → ctx.global；本脚本需复原 → ctx.local；重启可重算 → 内存（普通变量 / ctx.ref）；人改人看 → HA 实体
版本 flow.json由 script.js 反推画关键节点，不逐行也不笼统；它是只读投影，真相在脚本
仿真是临时态5.1 存在、跑完必须 finish 切回 follow；复现靠 fixtures 用例，不靠留着会话
